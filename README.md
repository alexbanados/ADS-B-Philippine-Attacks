# ADS-B-Philippine-Attacks

ADS-B-Philippine-Attacks is an ADS-B flight-trajectory project for preprocessing route data, generating attack and poison datasets, training/evaluating Keras models, and running the beta-testing GUI.

## How To Use: GUI

Make sure you have installed all the dependencies first, then activate the virtual environment.

Start the beta-testing GUI from the project root. Use 'cd' command to go to your project folder. Then, 

```bash
python betatesting_gui/server.py --port 8768
```

Then open:

```text
http://127.0.0.1:8768
```

Use `Ctrl-C` in the terminal to stop the server.

If port `8768` is already in use, choose another port:

```bash
/Users/alexbanados/Documents/ADSB/.venv_tf/bin/python betatesting_gui/server.py --port 8770
```

The GUI uses the curated beta-testing inputs in `betatesting/betatesting_data` and writes prediction CSV outputs to `betatesting/betatesting_results`.

If you prefer to use the terminal, scroll down and follow the instructions starting ## Environment.

## Project Overview

The project works with five route groups:

| Code | Route group |
| --- | --- |
| `ceb` | Cebu |
| `dvo` | Davao |
| `ilo` | Iloilo |
| `mph` | Malay / Caticlan |
| `pps` | Puerto Princesa |

The main workflow is:

1. Start from raw ADS-B CSV files in `dataset/raw/data_<route>`.
2. Preprocess each flight into route-aware, feature-rich CSVs.
3. Generate authentic, modified-altitude, modified-speed, and modified-position datasets.
4. Convert cleaned flight CSVs into fixed-length sequence windows.
5. Train or load route-specific Keras models.
6. Evaluate models on clean test splits and poison datasets.

NOTE: 2_statsandtypicalflight was only used in creating statistics from the gathered flight CSV for attack generation. This is not needed for testing/usage. Only use this if you want to use your own dataset or when adding flights to the current dataset. Same goes for 4_input/csv_9makewindows.py, this was used to create sequnce windows from the dataset.

The labels used by the project are:

| Label | Class |
| --- | --- |
| `0` | authentic |
| `1` | modified altitude |
| `2` | modified speed |
| `3` | modified position |

## Environment

Run commands from the project root:

```bash
cd <path-to-folder>
```

This cleaned project intentionally does not include `.venv_tf`. Virtual environments are large, machine-specific, and should be recreated instead of uploaded.

On another machine, create a new Python environment and install the packages listed in `DEPENDENCIES.md`, then point `PYTHON` to that environment's Python executable:

```bash
export PYTHON=/path/to/your/python
```

## How To Use: Command Line

### Inspect a model

Use this to check a saved `.keras` model and its nearby metadata:

```bash
"$PYTHON" 6_evaluate/inspect_model.py models/ceb_seq/best_model.keras
```

Add `--summary` if you also want Keras to load the model and print `model.summary()`:

```bash
"$PYTHON" 6_evaluate/inspect_model.py models/ceb_seq/best_model.keras --summary
```

### Evaluate a model on its held-out test split

`predict_unseen_balanced.py` asks for confirmation before running. The `printf 'y\n' |` prefix answers yes automatically.

```bash
printf 'y\n' | "$PYTHON" 6_evaluate/predict_unseen_balanced.py \
  --model models/ceb_seq/best_model.keras \
  --seq-folder dataset/data_ceb_seq \
  --manifest-split test \
  --output-csv docs/testsplit_results/ceb_seq/filepred_balanced_argmax4.csv \
  --confusion-matrix-csv docs/testsplit_results/ceb_seq/confmat_balanced_argmax4.csv \
  --classification-report-csv docs/testsplit_results/ceb_seq/classreport_balanced_argmax4.csv \
  --fnr-fpr-csv docs/testsplit_results/ceb_seq/fnrfpr_balanced_argmax4.csv
```

Change `ceb_seq` to any kept model folder, such as `ilo_par`, `dvo_seq`, or `pps_par`. The model folder and sequence folder should use the same route code.

### Evaluate a model on poison CSVs

Poison datasets are kept under `dataset/poison/<route>/<par-or-seq>`. For example, this evaluates the CEB parallel model against CEB poison CSVs generated by the sequence poison generator:

```bash
printf 'y\n' | "$PYTHON" 6_evaluate/predict_unseen_balanced.py \
  dataset/poison/ceb/seq \
  --recursive \
  --model models/ceb_par/best_model.keras \
  --seq-folder dataset/data_ceb_seq \
  --output-csv docs/poison_results/ceb/seqgen_on_parmodel/seqgen_on_parmodel_filepred_balanced_argmax4.csv \
  --confusion-matrix-csv docs/poison_results/ceb/seqgen_on_parmodel/seqgen_on_parmodel_confmat_balanced_argmax4.csv \
  --classification-report-csv docs/poison_results/ceb/seqgen_on_parmodel/seqgen_on_parmodel_classreport_balanced_argmax4.csv \
  --fnr-fpr-csv docs/poison_results/ceb/seqgen_on_parmodel/seqgen_on_parmodel_fnrfpr_balanced_argmax4.csv
```

### Print readable beta-testing predictions

```bash
"$PYTHON" 6_evaluate/betatesting_prediction.py
```

You can also pass specific file-level prediction CSVs:

```bash
"$PYTHON" 6_evaluate/betatesting_prediction.py \
  betatesting/betatesting_results/beta_ilo_par_on_seqpoison_filepred_argmax4.csv
```

### Generate new poison CSVs

Each route has a poison generator folder in `5_poison/pois<route>`. The generators write to `dataset/poison/<route>/par` or `dataset/poison/<route>/seq` by default.

```bash
"$PYTHON" 5_poison/poisceb/poiscebseq_gen.py --count-per-type 1
```

Use `--help` on any generator to see the available tuning options:

```bash
"$PYTHON" 5_poison/poisceb/poiscebseq_gen.py --help
```

### Rebuild sequence windows

The cleaned per-flight route datasets are in `dataset/data_<route>_ready`. Sequence arrays, scalers, metadata, and split manifests are in `dataset/data_<route>_seq`.

```bash
"$PYTHON" 4_input/csv_9makewindows.py ceb \
  --ready-folder dataset/data_ceb_ready \
  --output-folder dataset/data_ceb_seq \
  --overwrite
```

### Run preprocessing scripts

The raw datasets are in `dataset/raw/data_ceb`, `dataset/raw/data_dvo`, `dataset/raw/data_ilo`, `dataset/raw/data_mph`, and `dataset/raw/data_pps`.

Several preprocessing scripts rewrite input CSVs in place, while later scripts copy or create derived folders. If you want to preserve the curated snapshot exactly, run these on a working copy.

Example for the CEB raw folder:

```bash
"$PYTHON" 1_preprocess/csv_1preprocessing.py dataset/raw/data_ceb
"$PYTHON" 1_preprocess/csv_2segment.py dataset/raw/data_ceb
"$PYTHON" 1_preprocess/csv_3removemissingphases.py dataset/raw/data_ceb
"$PYTHON" 1_preprocess/csv_4trimmer.py dataset/raw/data_ceb
"$PYTHON" 1_preprocess/csv_5routeclassifier.py dataset/raw/data_ceb
```

Feature and sequence-preparation scripts can then be run as needed:

```bash
"$PYTHON" 1_preprocess/csv_6rmvlvl_addftrs.py dataset/raw/data_ceb --output-folder dataset/data_nolvl_ceb
"$PYTHON" 1_preprocess/csv_7derivefeatures.py dataset/data_nolvl_ceb
"$PYTHON" 4_input/csv_8cleanforseq.py ceb --base-dir dataset --overwrite
"$PYTHON" 4_input/csv_9makewindows.py ceb --overwrite
```

### Train models

Training scripts are kept in `training/`. The cleaned project keeps the best saved models in `models/`.

Example:

```bash
"$PYTHON" training/seqtcnlstm_train_keras.py \
  --data-folder dataset/data_ceb_seq \
  --output-folder models/ceb_seq_retrained
```

For the existing curated models, use:

```text
models/<route>_par/best_model.keras
models/<route>_seq/best_model.keras
```

## Folder Guide

### `1_preprocess/`

Preprocessing scripts for raw ADS-B CSVs. These handle timestamp cleanup, flight segmentation, missing phase removal, trimming, route classification, removal of the `is_level` column, and derived-feature calculation.

Important scripts:

| File | Purpose |
| --- | --- |
| `csv_1preprocessing.py` | Cleans raw flight CSVs, normalizes columns, adds Manila-local time, and renames files consistently. |
| `csv_2segment.py` | Adds flight phase segmentation. |
| `csv_3removemissingphases.py` | Finds or removes CSVs with missing phase data. |
| `csv_4trimmer.py` | Trims flights to useful route segments. |
| `csv_5routeclassifier.py` | Classifies flights by route and moves mismatches or bad routes to invalid data. |
| `csv_6rmvlvl_addftrs.py` | Copies route data, removes `is_level`, and adds blank feature columns. |
| `csv_7derivefeatures.py` | Computes derived movement and route-progress features. |
| `flight_segmentation.py` | Shared flight segmentation helper code. |

### `2_statsandtypicalflight/`

Scripts for computing route statistics and representative flight profiles.

| File | Purpose |
| --- | --- |
| `flight_statistics.py` | Computes route-level flight statistics and covariance matrices. |
| `generate_attack_tuning_statistics.py` | Creates statistics used by attack-generation scripts. |
| `generate_ideal_typical_flight.py` | Generates ideal or typical route profile CSVs. |
| `statistics_notes.txt` | Notes about the statistics workflow. |

### `3_attackgen/`

Attack-generation scripts for creating modified flight CSVs.

| File | Purpose |
| --- | --- |
| `mod_alt.py` | Generates modified-altitude attacks. |
| `mod_spd.py` | Generates modified-speed attacks. |
| `mod_pos.py` | Generates modified-position attacks. |
| `mod_tuner.py` | Shared attack tuning and generation logic. |

### `4_input/`

Scripts that prepare cleaned CSVs for model input.

| File | Purpose |
| --- | --- |
| `csv_8cleanforseq.py` | Builds route-specific ready folders containing authentic and modified CSVs. |
| `csv_9makewindows.py` | Converts ready CSVs into scaled sequence windows, metadata, scaler files, and train/validation/test manifests. |

### `5_poison/`

Route-specific poison-generation scripts and their poison-generator models.

Folders:

```text
5_poison/poisceb/
5_poison/poisdvo/
5_poison/poisilo/
5_poison/poismph/
5_poison/poispps/
```

Each folder contains parallel and sequence poison generators, route-specific poison `.keras` files, and visualization helpers where available. Generated poison CSV datasets are stored separately in `dataset/poison/`.

### `6_evaluate/`

Evaluation and reporting utilities.

| File | Purpose |
| --- | --- |
| `predict_unseen_balanced.py` | Runs file-level and optional window-level prediction on unseen CSVs, test splits, beta-testing files, or poison sets. |
| `betatesting_prediction.py` | Prints readable summaries from beta-testing prediction CSVs. |
| `inspect_model.py` | Inspects saved `.keras` models and nearby metadata. |
| `TESTING COMMANDS.xlsx` | Saved testing command notes. |

### `betatesting/`

Curated beta-testing data and result CSVs.

| Folder | Purpose |
| --- | --- |
| `betatesting/betatesting_data/` | Beta-testing authentic, modified, and poison input CSVs. |
| `betatesting/betatesting_results/` | Beta-testing prediction CSVs, confusion matrices, classification reports, and related outputs. |

### `betatesting_gui/`

The browser-based beta-testing GUI.

| File or folder | Purpose |
| --- | --- |
| `server.py` | Local HTTP server and backend actions for the GUI. |
| `index.html` | GUI page markup. |
| `styles.css` | GUI styling. |
| `app.js` | GUI client-side logic. |
| `artifacts/` | Intentionally empty tracked folder; generated GUI images are served from system temp instead. |

### `dataset/`

All kept datasets are grouped here.

| Folder | Purpose |
| --- | --- |
| `dataset/raw/data_<route>/` | Raw route CSV datasets. |
| `dataset/data_<route>_ready/` | Cleaned per-flight CSVs ready for window generation. Each route contains authentic, altitude, speed, and position subfolders. |
| `dataset/data_<route>_seq/` | Model-ready sequence arrays, scaler files, metadata, and split manifests. |
| `dataset/poison/<route>/par/` | Poison CSVs generated by parallel poison generators. |
| `dataset/poison/<route>/seq/` | Poison CSVs generated by sequence poison generators. |
| `dataset/data_XinvalidX/` | Invalid, non-Airbus, route-mismatch, or otherwise excluded CSVs created by preprocessing. |

The helper `dataset_paths.py` lets older commands that mention `data_<route>` resolve to the reorganized `dataset/` layout.

### `docs/`

Documentation, selected visualizations, and archived evaluation outputs.

| Folder or file type | Purpose |
| --- | --- |
| `docs/poison_results/` | Evaluation results copied from the old poison result folders. |
| `docs/testsplit_results/` | Clean test-split evaluation reports copied from archived model folders. |
| `*.png` | Kept visualization images, including selected `(2)` versions where multiple duplicates existed. |
| `COMPLEXITYVSACCURACY.csv` and `.xlsx` | Model complexity and accuracy summary data. |

### `models/`

Best kept models and their summary metrics. Each route has both a parallel and sequence model:

```text
models/ceb_par/
models/ceb_seq/
models/dvo_par/
models/dvo_seq/
models/ilo_par/
models/ilo_seq/
models/mph_par/
models/mph_seq/
models/pps_par/
models/pps_seq/
```

Each model folder keeps:

| File | Purpose |
| --- | --- |
| `best_model.keras` | Best saved Keras model for that route and architecture. |
| `best_test_metrics.json` | Best test metrics. |
| `best_classification_report.csv` | Classification report for the best model. |
| `best_confusion_matrix.csv` | Confusion matrix for the best model. |
| `run_config.json` | Training or run configuration metadata. |


### `statistics/`

Route-level statistics used for analysis and attack tuning.

Examples:

```text
statistics/ceb_stats4attk.csv
statistics/ceb_covmtx.csv
statistics/ceb_ideal_typical_flight.csv
```

Each route has corresponding statistics, covariance matrix, and ideal typical flight files.

### `training/`

Training scripts for LSTM, TCN, parallel TCN-LSTM, and sequence TCN-LSTM models.

| File | Purpose |
| --- | --- |
| `train_lstm_maxpool_keras.py` | LSTM model with global max pooling. |
| `train_tcn_maxpool_keras.py` | TCN model with global max pooling. |
| `partcnlstm_train_keras.py` | Parallel TCN-LSTM model. |
| `seqtcnlstm_train_keras.py` | Sequential TCN-LSTM model. |

Scripts to visualize flights using matplotlib. Also, 

Scripts for producing project figures from saved reports and statistics. For example, `plot_macro_accuracy_test_poison.py` reads from `docs/testsplit_results` and `docs/poison_results`.

## Upload Notes

- `.venv_tf` is intentionally not included. Recreate the environment from `DEPENDENCIES.md`.
- `betatesting_gui/artifacts` should stay empty. GUI-generated images are temporary and are not meant to be uploaded.
- If uploading the project to GitHub, consider Git LFS for large `.keras`, `.npy`, and `.csv` files.
- Run commands from the project root so relative paths resolve correctly.
